## Bug: No CSRF Protection

**Severity:** MEDIUM — form bisa di-submit dari domain lain tanpa token CSRF

**File:** Semua blueprint yang menggunakan `request.method == 'POST'` tanpa verifikasi CSRF

### Root Cause
Tidak ada mekanisme CSRF protection di aplikasi:
- Tidak ada `flask-wtf` atau `WTForms` CSRF token
- Tidak ada custom CSRF token di form
- Session cookie tidak memiliki `SameSite` attribute (tambahan risiko)

Semua form POST (login, settings, landing page, customer management, dll.) rentan CSRF.

### Attack Scenario
1. Attacker buat website jahat dengan hidden form yang auto-submit ke `http://103.253.213.111/settings/`
2. Admin yang sedang login mengunjungi website jahat
3. Form ter-submit dengan kredensial session admin → settings berubah

### Impact
- Attacker bisa mengubah settings aplikasi (payment gateway, landing page, dll.)
- Membuat/menghapus admin user
- Mengubah konfigurasi router

### Fix
Beberapa opsi:
1. **Flask-WTF CSRF:**
```python
from flask_wtf.csrf import CSRFProtect
csrf = CSRFProtect(app)
```
2. **Custom token:** generate token di session, validasi di setiap POST
3. **Minimal:** set `SESSION_COOKIE_SAMESITE = 'Lax'` atau `'Strict'`
