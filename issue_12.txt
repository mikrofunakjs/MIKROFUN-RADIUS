## Bug: Landing Page Custom Template SSTI Risk

**Severity:** LOW (perlu admin akses dulu, tapi landing page publik)

**File:** `web/app.py` line 349-389

### Root Cause
Rute `/landing-page` (PUBLIK, tanpa auth) merender custom HTML user dari settings sebagai Jinja2 template:

```python
if template_choice == 'custom':
    return safe_render_template_string(custom_html, company=company, packages=packages)
```

Ini berarti:
1. Siapapun bisa mengakses `/landing-page` — endpoint publik
2. Custom HTML di-fetch dari database settings
3. Dirender sebagai Jinja2 template dengan SandboxedEnvironment (yang sudah dijebol via format_rupiah filter — lihat issue #5)

### Impact
- Jika admin jahat atau akun admin di-takeover, attacker bisa inject malicious template yang:
  - Mengeksekusi arbitrary code via SSTI sandbox escape
  - Inject JavaScript untuk phising/credential theft ke pengunjung landing page
- Landing page adalah halaman publik pertama yang dilihat pelanggan

### Fix
1. **Jangan render sebagai Jinja2 template** — ganti dengan string formatting atau replace sederhana:
```python
html = custom_html.replace('{{company_name}}', company.get('name', ''))
# atau gunakan string.Template yang lebih aman
```
2. Jika tetap ingin Jinja2, gunakan strict sandbox TANPA custom filter sama sekali
3. Validasi/sanitasi HTML sebelum disimpan (strip semua `{{` dan `{%`)
