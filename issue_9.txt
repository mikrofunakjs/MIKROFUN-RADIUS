## Bug: No Rate Limiting on Login

**Severity:** MEDIUM — attacker bisa brute force password tanpa hambatan

**File:** `web/blueprints/auth/__init__.py` line 40-104

### Root Cause
Endpoint `/auth/login` tidak memiliki mekanisme rate limiting. Tidak ada:
- Rate limit per IP
- Rate limit per username
- Account lockout setelah N percobaan gagal
- CAPTCHA setelah percobaan gagal
- Delay response yang meningkat

### Impact
- Attacker bisa brute force password admin/user tanpa terdeteksi
- Tidak ada logging percobaan login gagal
- Kombinasi dengan error message "Username atau password salah" (line 102) memungkinkan enumerasi user (attacker tahu username valid jika error berbeda — meskipun saat ini error message sudah generic)

### Fix
Beberapa opsi:
1. Flask-Limiter: `@limiter.limit("5 per minute")` pada endpoint login
2. Account lockout: setelah 5x gagal, kunci akun 15 menit
3. Log percobaan gagal ke database untuk monitoring
4. Tambahkan increasing delay (1s, 2s, 4s, 8s...)

```python
from flask_limiter import Limiter
limiter = Limiter(app, key_func=get_remote_address)

@auth_bp.route('/login', methods=['GET', 'POST'])
@limiter.limit("10 per minute")
def login():
    ...
```
